# 发版流程（每版必做）

每次发新版，**必须**做下面 4 步，保证客户端能弹出本版更新日志。

## 1. 更新 web/index.html 两处

打开 `web/index.html`，找到 `const APP_VERSION` 和 `const CHANGELOG`：

```js
const APP_VERSION='2.10.45';        // ← 改成新版号
const CHANGELOG={
'2.10.45':['更新日志改成按版本号弹…','每次发版自动带上本版更新内容'],  // ← 新版条目加在最上面
'2.10.44':['…'],
...
};
```

**规则**：
- `APP_VERSION` 必须和 `build.gradle` 的 `versionName` **完全一致**
- 新版条目加在 `CHANGELOG` 对象**最上面**（最新在前）
- 每条是一句话，用户看得懂的改动

## 2. 改 build.gradle 版本号

```gradle
versionCode 91                    // ← +1
versionName "2.10.45"             // ← 和 APP_VERSION 一致
```

## 3. 构建 + 测试

```bash
python tests/out/checkjs.py                    # JS 语法
node tests/smoke_ui.js                         # UI 回归 184 条
node tests/aura_e2e.js                         # AURA e2e 64 条
bash tools/build_apk.sh release                # 构建
```

## 4. 提交 + 发布

```bash
git add -A
git commit -m "release: X.Y.Z …"
git tag -a vX.Y.Z -m "X.Y.Z"
python tools/create_release.py X.Y.Z
```

## 客户端弹窗逻辑（已内置，无需再改）

- 存 `changelog_seen` = 上次看过的版本号
- 启动时读当前版本（`Android.getVersion()`，web fallback `APP_VERSION`）
- **当前版本 ≠ 已看版本** → 弹窗显示 `CHANGELOG[当前版本]`
- 点「已经看了」→ 存 `changelog_seen=当前版本`，同版本不再弹
- 出新版 → 自动弹新版内容

## 注意

- `CHANGELOG` 里没有当前版本的条目时，会 fallback 显示 `APP_VERSION` 的条目
- 千万别忘了第 1 步 —— 忘了就没有本版更新内容（会显示 fallback）
