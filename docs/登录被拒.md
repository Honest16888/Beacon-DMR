# 登录被拒（MSTNAK）：怎么一步步排除

主站拒绝登录时只回一个 10 字节的 `MSTNAK`，**不带任何原因**。
唯一能利用的信息是「我们当时处在握手的哪一步」—— 代码里靠这个分诊。

## 一、四个阶段，四种病因

| 被拒时状态 | 握手走到哪 | 含义 |
|---|---|---|
| `CONNECTING` | 刚发 RPTL，连 salt 都没拿到 | **这个登录 ID 已经有会话在线**，与密码无关 |
| `AUTH` | 已回 RPTK（salt+密码的 SHA-256） | 密码摘要不对，或该 ID 没在 SelfCare 设过热点密码 |
| `CONF` | 已发 RPTC 配置串 | 密码**已经通过**了；是呼号 / 软件标识 / 包名被拒 |
| `CONNECTED` | 三次 RPTACK 全走完 | **不当作拒绝**：这是上一次尝试的延迟报文，忽略 |

`CONNECTED` 那一行很关键。主站真要踢掉一个已建立的会话，发的是 `MSTCL`，不是
`MSTNAK`。早先把 `CONNECTED` 时收到的 `MSTNAK` 当成「被顶掉」→ 主动断开重连 →
重连又发 RPTL → 又制造一个延迟 `MSTNAK`，形成
「连上 → 发射一次 → 显示拒绝登录 → 重连」的死循环。

## 二、实测案例：同一份凭据，11 分钟前还是好的

```
14:26:01  RPTL → RPTACK(salt D70BB3B9) → RPTK → RPTACK → RPTC → RPTACK → 已连接 ✓
14:27:07  最后一次发射
          （装 v2.3，安装器强杀进程）
14:37:11  RPTL → RPTACK(salt F44FC1A6) → RPTK → MSTNAK ✗
```

「密码不对」这个结论在这里是**错的**。逐条排除：

1. **不是重装丢数据。** 两个 APK 的签名证书 SHA-256 完全相同
   （`27f95f5b…bf03`，`CN=Beacon DMR`），说明是覆盖安装，SharedPreferences 保留。
   日志里 DMR ID、主站地址、描述串都还在，也印证这一点。
2. **不是空密码。** 前端 `if(!pwd)return toast('请填热点安全密码');` 直接拦住，
   根本不会发起连接。
3. **不是密码被改。** v2.4 起日志里会打密码指纹（SHA-256 前 8 位），
   两次登录指纹一样就是同一个密码。
4. **不是代码改动。** v2.3 只动了 `DmrTransmitter.txLoop`（发包节拍），
   握手链路一个字节都没碰。

## 三、剩下的可能，按可能性排序

1. **主站还挂着上一次的会话。** 安装器强杀进程时没有机会发 `RPTCL`（登出），
   主站要等自己超时。更麻烦的是：如果这期间手机换了网络（WiFi ↔ 移动数据），
   新登录来自**不同的公网 IP**，主站会按「一个 Radio ID 只允许一台热点在线」
   判成幽灵热点，直接回 `MSTNAK`。
   → 等 2~5 分钟再连一次；或去 SelfCare → Hotspots 看有没有多余的在线记录，手动断开。
2. **短时间失败次数太多，主站临时限流。** 本 App 的退避是
   10 / 20 / 30 / 45 / 60 秒（累计约 165 秒），不算激进，但连续几轮也会触发。
   → 停 10 分钟。
3. **同一个 DMR ID 在别的设备或热点上在线。** 同上。
4. **公网 IP 变了。** 一般不影响，但 BM 偶尔认旧 IP。

**在这几种情况下重设密码只会让情况更糟** —— 改完之后旧密码就真的对不上了，
而新密码还要等 BM 同步。**先别动密码。**

## 四、绕过「同 ID 占用」：ESSID 别名

协议允许同一个 Radio ID 用 `ID × 100 + (ESSID - 1)` 的形式登录，ESSID 取 1~99。
对主站来说这是一个**不同的热点 ID**，于是「一台热点在线」的限制就不再冲突。

代价：BM 上会多出一条热点记录，业务包里的 `srcId` 仍是裸 DMR ID
（呼号和通联归属不受影响），只有 `repeaterId` 字段用别名。

## 五、v2.4 加了什么

- **密码指纹**：`密码指纹 3f9a1c02（8 字符）`。不含明文，但能回答
  「密码到底有没有变」。空密码 / 超过 20 字符会当场标 ⚠。
- **空密码不再重试**：直接停机并说明去哪儿填。空密码重试 5 次只会让主站
  把这条热点临时锁掉。
- **`AUTH` 被拒时对照指纹**：如果这份密码在本机 2 小时内通过过校验且指纹相同，
  报错里会明确写「先别改密码」，并列出主站侧的四个原因 ——
  原来的文案只有「密码不对」，会把用户引到完全错误的方向。
